# Автотесты для API Музея Метрополитен

Тестовое задание: автотесты для Met Museum Collection API (https://metmuseum.github.io).
Стек: Python, Pytest, Pydantic v2, requests.

## Установка и запуск

```bash
python -m venv .venv
pip install -r requirements.txt
python -m pytest
```

Активация виртуального окружения (перед `pip install`):
- Windows PowerShell: `.venv\Scripts\Activate.ps1`
- Linux и macOS: `source .venv/bin/activate`

Другие варианты запуска:

```bash
python -m pytest -m smoke           # только базовые проверки
python -m pytest -m "not bulk"      # без массовых проверок (много запросов)
python -m pytest test_search.py     # один файл
python -m pytest -q -o log_cli=false   # короткий вывод без логов в консоли
```

## Структура проекта

| Файл | Что внутри |
|------|-----------|
| `models.py` | Pydantic-модели ответов API |
| `client.py` | клиент для запросов, логирование, повторы при блокировке |
| `helpers.py` | параллельная загрузка объектов |
| `conftest.py` | фикстуры (клиент, список отделов, ID для проверок) |
| `test_objects.py` | получение объекта по ID, список `/objects` |
| `test_search.py` | поиск, пагинация, фильтры, сортировка |
| `test_departments.py` | список отделов |
| `test_performance.py` | время ответа, серии и параллельные запросы |

## Что проверяется

**Модели Pydantic** (`models.py`): объект произведения (`MetObject`), ответы со списком ID (`ObjectsListResponse`, `SearchResponse`), отделы, ошибки. В `MetObject` есть дополнительные проверки, например что `objectURL` ведёт на сайт музея.

**Объект по ID**
- статус 200 и соответствие модели;
- несуществующий ID (404), нечисловой ID (400), ID 0 и -1 (404);
- проверка по модели примерно 30 объектов, загруженных параллельно.

**Поиск**
- поиск по 10 ключевым словам, структура ответа проверяется моделью;
- пустой результат, регистр букв, спецсимволы, несколько слов;
- пагинация: `limit` (по умолчанию 100, максимум 500) и `offset`, страницы не пересекаются;
- фильтры: `isHighlight`, `hasImages`, `isOnView`, `tags`, `geoLocation`, `departmentId`, `artistOrCulture`, `title`, `medium`, `dateBegin`/`dateEnd`;
- сортировка: в API её нет, поэтому проверяется, что порядок стабилен, а параметры сортировки не влияют на результат.

**Дополнительно:** список отделов, время ответа, серия из 20 запросов подряд, параллельные запросы.

## Логирование

Логируются запросы, ответы (статус и время), тело ответа и ошибки.
- В консоль идёт краткий лог (уровень INFO).
- В файл `logs/test_run.log` пишется подробный лог (уровень DEBUG), включая начало тела ответа.

Пример:

```
REQUEST  GET .../v1.1/search params={'q': 'monet'}
RESPONSE .../v1.1/search?q=monet status=200 time=0.412s
HTTP 404: {"message":"ObjectID not found"}
```

## Что я заметил при работе с API

1. **Старый эндпоинт `/v1/search` отключён с 01.10.2026** и отвечает кодом 410. Поэтому поиск тестируется через `/v1.1/search`, где добавились параметры `offset` и `limit`. Отдельный тест проверяет, что старый адрес действительно отключён.
2. В `/v1.1/search` поле `total` показывает число всех совпадений, а в `objectIDs` приходит только одна страница. Больше 10 000 результатов получить нельзя (`offset + limit` не больше 10 000).
3. Сервер защищён файрволом, который иногда отвечает 403 и HTML-страницей. Из-за этого клиент ограничивает частоту запросов (около 20 в секунду) и повторяет заблокированный запрос через 2, 4 и 8 секунд. В логе это видно по сообщению `WAF заблокировал запрос`.
4. Тесты работают с живыми данными музея. Если коллекция изменится, некоторые ожидания (например, количество результатов) может потребоваться поправить.
